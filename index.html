High-frequency source control for AI agents

Every agent edit, saved.
Git never knows it was there.

ghf (Git High Frequency) checkpoints your worktree every time an agent finishes an edit. Any authorized agent, on any machine, can go back to it: restore, diff, apply or fork. Your commits stay exactly as they are.

01 · The problem

Agents make hundreds of edits between two commits. Most of them disappear forever.

Git was built around human-sized decisions. Between commits, coding agents pass through the last green state before a bad refactor, the approach that almost worked, the attempt another model was making. Then it is gone.

  • Harness undo is local. It is tied to one session, and gone with the machine.
  • WIP commits pollute history. They mix working history with accepted history.
  • Agents can't pick up each other's state. With many agents on many machines, one cannot continue from another's exact files.
  • Humans can't see what was tried. A person taking an escalation has no record of the attempts.

02 · How ghf works

A layer below commits.
Git stays canonical and is only read.

Git

holds accepted history: commits, branches, pull requests.

ghf

holds recoverable working history, with its own retention, permissions and sync.

Nothing else changes

No commits, trailers, notes or refs. Plain Git users never need to know ghf exists.

1

Checkpoints

A complete, independently restorable worktree state, captured by Claude Code and Cursor hooks after each tool call, or by git hf checkpoint.

2

Traces

The checkpoints for one unit of work. Any authorized agent can list, diff, restore, apply or fork it.

3

Its own lifecycle

Traces close, finalize against the commit that landed, and are pruned 30 days later. Pins and holds keep what matters. Pruning never touches Git.

Back to the last green state in two commands

Tests passed, then a later step broke them. Find the last checkpoint annotated tests=pass and restore it. No WIP commit, and the restore is itself recorded as a checkpoint.

$ git hf trace log --annotation tests=pass
#7    ck_01m5054dg9rkmmeasv0rcxd8x0  2026-10-15T16:08:12Z  2 change(s)  claude-code:s1  [tests=pass]
$ git hf trace restore ck_01m5054dg9rk --in-place
restored ck_01m5054dg9rkmmeasv0rcxd8x0 in place (2 written, 1 deleted); recorded as ck_01m5054dmjth7gspksqcfddsh0

What it does for an agent fleet

Roll back to last green

Tests passed, then a later step broke them. Return to the last checkpoint annotated tests=pass, without a WIP commit.

Hand off between machines

Another worker continues from the exact file state, uncommitted changes included.

Fork an attempt

Two models try different approaches from the same checkpoint, each in its own worktree and trace.

Show a human what was tried

When a run escalates, list the trace and diff any two points.

Survive a crash

A checkpoint is acknowledged only once it is durable locally. Sync catches up when the network returns.

Quick start

Where the pieces live

Safe by default

Restore never eats work.

↳Restore goes to a new worktree

Restore goes into a new worktree by default. In-place restore and apply refuse if anything uncaptured would be lost.

⇄Apply is all or nothing

A conflict on any path means nothing is applied and the working tree is unchanged.

↺Every restore is a checkpoint

Going back is itself recorded in the trace, so a restore never erases where you were.

■Every checkpoint is complete

A checkpoint is the full worktree state, stored as content-addressed objects (BLAKE3, zstd). Each one restores on its own, and unchanged directories are shared.

1One writer per worktree

Parallel agents use separate Git worktrees, each with its own trace. A second writer gets E_WRITER_LOCKED.

∅Nothing written into Git

No commits, trailers, notes, refs or objects in Git. ghf keeps its own store under .git/ghf.

Built for agents

Built for agents to call

Every command takes --json and returns one versioned envelope with stable error and exit codes. Nothing prompts in automation, and mutating commands accept an idempotency key.

  • Versioned --json on every command
  • Stable error and exit codes
  • No prompts in automation
  • Idempotency keys for mutating commands
{"schema":"ghf/v1","command":"trace apply","ok":false,
 "error":{"code":"E_APPLY_CONFLICT","message":"1 conflicting path(s); the working tree is unchanged"},
 "data":{"applied":false,"conflicts":[{"path":"src/lib.rs","reason":"content changed on both sides"}]}}

Self-hosted

Your own ghf-server

Every team runs its own ghf-server: one Rust binary plus a data directory, with repository-scoped tokens.

  • One Rust binary plus a data directory
  • Repository-scoped tokens
  • Read-only web viewer of each trace's timeline, annotations, forks and diffs

Quick start

  1. Run a server

    ghf-server --data-dir /var/lib/ghf token create --name fleet --repos 'acme/*'
ghf-server --data-dir /var/lib/ghf serve --listen 0.0.0.0:7878 \
  --tls-cert cert.pem --tls-key key.pem

  2. Enable a repository

    git hf init --server https://ghf.example.com --repository acme/project
git add .ghf && git commit -m "Enable ghf"

  3. Set up each machine

    git hf trust
echo "$GHF_TOKEN" | git hf login
git hf hooks install claude-code   # or: cursor
git hf skill install

That's it: every agent edit is now a checkpoint. The user guide covers the rest.
